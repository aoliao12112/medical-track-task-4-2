# 第四问：品质画像与可解释推荐方案

## 当前完成范围

第四问现在包含四层：

1. 从病例图片提取医院及带职责的医生，生成稳定脱敏编号；
2. 按“主体 × 病种”聚合医院、医生和治疗方案画像；
3. 对数据不足的维度显式返回不可用或样本不足；
4. 只对通过准入门槛的画像生成排序，并给出至少两条可回溯理由。

网页“品质推荐”页展示真实机构覆盖审计。当前不会展示真实排行榜，因为机构冲突尚未全部人工确认，70例也尚未全部完成第一、二问结构化。

## 六个维度

| 维度 | 当前计算口径 | 重要边界 |
|---|---|---|
| 费用效率 | 同病种费用中位数反向百分位；住院优先使用日均费用 | 尚未做严重度、年龄和合并症风险调整 |
| 用药合理性 | 按第二问有原文证据的用药复核痛点扣分 | 不是药师处方点评；缺报告不能默认满分 |
| 治疗记录规范性 | 诊断、日期、手术、用药要素和事件证据完整度 | 只是代理指标，不能冒充指南依从性 |
| 30日再入院控制 | `100 × (1 - 再入院率)` | 必须有稳定脱敏患者标识；案件号不能代替 |
| 患者反馈 | 5分制均值换算为百分制 | 当前材料无反馈，禁止由LLM生成 |
| 数据质量 | 字段置信度均值减质量标记惩罚 | 衡量数据可信度，不代表医疗质量 |

## 推荐准入门槛

- 只在同一病种、同一主体类型内比较；
- 默认每个主体至少 3 个病例，正式上线应提高门槛；
- 至少 3 个维度同时达到“可计算且样本达标”；
- 综合分由可计算维度按权重重新归一化，缺失维度不补零；
- 每项推荐至少给出 2 条理由，理由包含维度得分、样本量、计算方式和字段路径；
- 没有合格候选时返回“拒绝推荐”，不降门槛凑结果。

## 标准输入

每个 `ProfileCaseRecord` 包含：

- 第一问 `ClaimCase`；
- 脱敏 `institution_id`；
- 标准病种分组 `disease_group`；
- 可选的带职责 `clinician_ids`；
- 可选治疗方案编号；
- 可选稳定患者标识、30日再入院标签和患者反馈；
- 可选第二问 `PainPointReport`。

医生编号只纳入主治、经治和手术角色。报告、检验、审核医生不得进入经治医生排名。

## API

```text
GET  /api/quality/audit-summary
POST /api/quality/profiles/build
POST /api/quality/recommendations
```

离线批量生成：

```powershell
& '.\.venv\Scripts\python.exe' '.\scripts\build_quality_profiles.py' `
  '.\work\quality\profile-records.json' `
  '.\work\quality\result'
```

生成：

- `quality-portfolio.json`：医院、医生和治疗方案画像；
- `quality-recommendations.json`：逐病种、逐主体类型的推荐结果或拒绝原因。

## 当前真实数据结论

机构审计覆盖 70 个案件、728 张图片。候选层面肺炎、流感和高血压均覆盖至少5家机构，但其中多机构冲突尚未人工确认，因此只能作为可行性证明，不能作为正式排行榜或医疗质量结论。
