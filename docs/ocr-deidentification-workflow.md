# OCR 脱敏与人工复核流程

本文说明第一问真实病例如何在“原图不离开本机”的前提下完成 OCR、人工修正、脱敏确认、
DeepSeek 结构化和审计。比赛演示和团队联调都应遵循本流程。

## 数据流

```text
本地病例图片
  → RapidOCR（仅本机）
  → SQLite中的OCR待复核稿
  → 人工逐页修正和脱敏
  → 敏感格式规则预警
  → 人工确认或明确覆核
  → 同一份修改后的OCR文本发送给DeepSeek
  → 结构化病历、痛点、温度指引
```

原图不写入 SQLite，也不发送给 DeepSeek。SQLite 保存逐页 OCR 文本、OCR 块坐标、人工修正
标记和当前下游结果快照。`outputs/competition.db` 已被 Git 忽略，不得复制到公开仓库。

## 页面操作

1. 创建案件时确认医疗材料已有合法使用授权。
2. 添加同一案件的全部 JPG/PNG 图片。
3. 点击“① 仅运行本地OCR”。此步骤调用 `POST /api/cases/ocr-only`，不会调用 DeepSeek。
4. 逐页展开“查看、脱敏或修正 OCR 文本”。
5. 删除或替换姓名、身份证号、手机号、家庭住址、条码/二维码内容及个人医疗编号，同时核对
   模糊字、金额、单位、日期和否定词。
6. 每页点击“保存本页修正”。页面调用 `POST /api/cases/save-reviewed-ocr`，把当前全部修改版
   OCR 写入 SQLite，不调用外部模型。
7. 全部页面完成后勾选“我确认发送给外部模型的OCR文本已完成脱敏”。
8. 若自动规则仍命中虚构占位符、医院公共电话或非患者编号，必须逐项核实后再勾选人工覆核。
9. 点击“② 使用脱敏文本结构化”或“应用脱敏文本并重新结构化”。

优先使用明确占位符：

```text
姓名：[已脱敏]
身份证号：[已脱敏]
手机号：[已脱敏]
家庭住址：[已脱敏]
住院号：[脱敏编号-001]
```

不建议使用格式逼真的虚构身份证号或手机号。它们可能触发规则，也可能误撞真实号码。

## 自动规则与人工覆核

规则当前预警以下类别：

- 身份证字段及18位证件格式；
- 11位手机号和联系电话；
- 住址或地址；
- 病历号、门诊号、住院号、影像号、标本号和 ID 号。

规则只做高召回预警，不能证明文本一定包含真实个人信息。允许人工覆核的前提是操作者已经逐项
确认命中内容属于虚构占位符、医院公共信息或其他非患者身份信息。人工覆核不是“一键忽略”，
后端会重新扫描请求中的修改版文本；存在规则命中但请求未明确人工覆核时返回 `409`。

确认成功后，`system_logs` 会记录：

- `action=confirm_deidentification`；
- `review_method=rule_clear` 或 `manual_override`；
- 规则命中类别；
- 修改版文档的 SHA-256 指纹；
- 操作时间。

审计日志不额外复制 OCR 原文。

## 修改版与原始版的使用关系

| 操作 | 浏览器内存 | SQLite | DeepSeek |
|---|---|---|---|
| 本地OCR完成 | OCR原始识别文本 | 保存OCR原始识别文本 | 不调用 |
| 编辑文本框但尚未保存 | 当前修改版 | 仍是上次保存版 | 不调用 |
| 保存本页修正 | 当前修改版 | 保存全部当前修改版，脱敏状态重置为待复核 | 不调用 |
| 确认并重新结构化 | 当前修改版 | 先保存同一份修改版 | 只接收同一份修改版 |

页面会在切换页或提交前自动采纳当前文本框内容，避免因漏点“保存”而继续检查旧文本。但正式
操作仍应逐页点击保存，以便刷新页面后可以从 SQLite 恢复。

## API 摘要

```text
POST /api/cases/ocr-only
POST /api/cases/save-reviewed-ocr
POST /api/cases/restructure-from-ocr
```

重新结构化请求的关键字段：

```json
{
  "case_id": "CASE-ID",
  "documents": [],
  "deidentification_confirmed": true,
  "manual_override_confirmed": false,
  "sensitive_pattern_findings": []
}
```

`sensitive_pattern_findings` 是前端说明信息，后端会独立扫描 `documents[].full_text`，不信任
前端自行声称“没有命中”。

## 结果失效规则

保存新的 OCR 复核稿会清空旧的结构化病历、痛点报告、温度指引和案件画像上下文，并将工作流
退回 `OCR_READY`。这是必要的一致性保护：下游结论不能继续引用已经修改的 OCR 事实。
